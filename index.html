两种记忆，一起参与召回03 / 18

Scene 与 Event，
分别留下什么？

同一段经历，可以有不同的记录视角。

01 / SCENE

主窗口主动想留下的

片段、理解、感受或约定。正在和你聊天的模型，主动调用工具写下。

她把车票收了起来。
我也想把第一次一起
出发的这段路留下。

02 / EVENT

依据原话整理经历

自动流水线整理发生过、讨论过的内容，不补写原话之外的感受与后续。

她留下车票，说想
记住第一次一起出发。

两者一起召回，互相补充。一段话不必各存一份。

车票内容为虚构示例。Scene 包含主窗口的理解，Event 也可能整理有误；核对事实时，仍要回到原话。

自动召回 · 机制图解05 / 18

记忆，怎样进入上下文？

01 / ELIGIBILITY

先判断资格

这轮要不要找？哪些记忆可以参与？

原句与语义路由

一次 query embedding，判断 skip / recall 边界；可以在候选生成前结束。

批量资格过滤

检查 active、可浮现与当前版本；排除替换、完整覆盖的 Event，以及主域、排除 ID 和旧索引等不合格对象。

Event ＋ Scene → 可检索对象

02 / NOMINATION

把候选送到门口

四种信号，进入同一个混合候选池。

  • 正文 / passage 向量
  • Scene cue 语义
  • Event 特定关键词
  • 完整实体名

前 6 条宽探针；其余候选须有扩展证据。实体名需要回忆意图或明确结构。

已确认 Scene 关系：最多 1 个邻接候选，不加分。

03 / ADMISSION → DELIVERY

筛选，再交付

搜到了，不等于已经带入。

正文 reranker

完整原句 × 候选正文，最终门槛默认 ≥ 0.65。

选卡与会话冷却

默认最多 2 张。胜出后检查冷却，取消后不补位。

Gateway 直接加入卡片；Hook 由宿主实际注入并登记结果。

向量扩展默认 ≥ 0.50，cue 扩展默认 ≥ 0.55。准备、渲染与实际交付分别留痕，候选不直接等于注入。

召回设置与设计取舍06 / 18

一句只有你们懂的话，
也可能需要记忆。

没有明显的回忆意图，也可能藏着重要前情。

不了解这些经历的模型，可能在看到记忆之前，就把门关上。

所以，不额外让生成式小模型先决定“准不准查”。用例句与向量做入口判断，再筛选实际候选，减少额外生成调用与等待。

例句维护
调整继续召回、跳过与容易混淆的边界。它在校准入口，不是在补写记忆。
召回门槛
候选扩展与最终准入可分别设置。用召回模拟对照结果，再保存调整。
长文分段
自行设定起切字数，让长记忆的细节能被找到。切的是检索片段，正文仍是一条完整记忆。

入口仍可能误判；阈值不能保证准确。长文分段是可选项，起切门槛不等于每段长度，片段向量需要 Embedding。

自动 Event · 机制图解08 / 18

原话，怎样长成 Event？

01 / SOURCE & CLOCK

等待完整的对话

原始消息持续归档

成功回复、正文与附件。完整回复包用于调度，未完成尾巴继续等待。

两种调度时机

白天：同一会话至少 5 个完整回复包，且静默至少 20 分钟。

每日上海时间 03:00：稳定材料结算，活跃尾部等待。

回复包粗分等待边界；消息仍逐条归线。

02 / ROUTE & CURATE

归线，再切分整理

Track Router

逐条归线。Track 不是 Event 边界。

Curator

判断 create / extend / merge，或 skip / defer。图片逐张转录。

宿主校验与冻结

校验判断回执，冻结来源归属。桥接共同阅读，不自动增加来源；保护旧 Event。

03 / WRITE & SETTLE

写作，校验，落库

Event Writer

只读冻结原话、前版正文与已校验转录，不接收原图。

结构校验与有限修复

核对结构、来源和可选证据收据。校验不证明正文语义准确。

幂等结算 → 正式 Event ＋ 原话绑定 ＋ 写入回执。

成功步骤保留，可安全重试。文字步骤累计失败三次后暂停；同一聊天等待，其他聊天继续，图片单独计失败预算。

落库后，可选自动归入已有叙事卷；也可由主模型读原话后编辑、升为 Scene。这些都不是落库前的必经步骤。

日期和停顿安排处理批次，不单独决定 Event 的边界。

同一段后续
符合续接条件时，读取旧正文、旧原话和新材料，形成更新版本，保留重要经过与变化。
新的经历
可以在同一条 Track 下另建 Event，不必把一个话题的全部历史塞进同一条。
跨线有联系
有明确桥接材料并开启联合审阅时再判断。主题相似，不足以直接合并两条线。

讨论、玩笑、共同体验都可能留下；单纯状态汇报可跳过。尚未生成时，可查看是在等待、受保护，还是执行失败。

关系提案与记忆管理10 / 18

有些记忆相连，
有些只是舍不得丢。

两条 Scene 的联系，可以由你提出，也可以由模型寻找。

Scene A

提案 → 校验 / 审核 → 确认

手动提出，或由模型生成
Scene B

相连的记忆

关系提案核对当前正文、方向和原文证据。逐条审核，或单独开启“关系提案自动通过”。

开启联想后，已确认关系最多帮助一条 Scene 进入候选池；它仍要经过同样的相关性筛选。

收藏，是另一件事

Scene 和 Event 都可以收藏，方便再次阅读。开启收藏工具后，主模型也可以读写收藏。

收藏不加召回分，也不绕过冷却。还可以编辑、归档、管理自动浮现资格。

联想、关系提案自动通过和收藏工具分别控制。
